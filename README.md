# can_policy

The community-legislated policy pack of the Community Action Network (CAN). A policy pack is the versioned set of platform rules, thresholds, decision-point prompts, content schemas and simulation data that the CAN server loads by version and content hash. Contributors change moderation by pull request here.

All examples in this repository are fictional or synthetic and contain no real people.

## Layout

| Path | Holds |
|---|---|
| `packs/base/` | platform rules and thresholds |
| `packs/constitution/` | constitution rules as a pack layer |
| `packs/jurisdictions/<id>/` | jurisdiction overlays |
| `content-schemas/<type>/` | one versioned schema per content type |
| `decision-points/<DP-id>/` | prompt, output schema, examples and eval sets per decision point |
| `simulation/` | personas, seed scenarios and thresholds (data only) |
| `ratifications/` | ratification records (append-only) |
| `ci/` | CI checks |
| `tools/` | pack tooling, including the pack hash |
| `CHANGELOG.md` | human-readable version history |

Full specification: `docs/design/components/can-policy.md` and `docs/design/ai/policy-pack.md` in the superproject.

## Propose a change

1. Fork and branch.
2. Edit the pack files. Never hand-edit `manifest.json` or `release.json`; they are generated.
3. Run `npm run verify`.
4. Open a pull request. CI runs schema lint, eval against labeled sets and a replay diff. Ratification follows the amendment loop in `docs/design/ai/amendment-loop.md` in the superproject.

## Verify

```
npm ci
npm run verify     # lint, then the Node test runner
npm run eval       # stub until 10-u23
npm run replay     # stub until 10-u24, reads test/fixtures/replay-decisions.json
npm run build:pack # writes manifest.json per pack and release.json
```

Dependencies are exactly `ajv` and `yaml`, pinned. `lint` checks pack.yaml files, decision point folders, content schemas, file size (256 KB), banned dashes, and that generated manifests match the sources (`build:pack --check`). Pack YAML stays in a simple subset (block maps and lists, inline lists, scalars, comments; no anchors, multiline scalars or flow maps) because the server parses it with a small reader.

## Pack format

- One repo wide semver per git tag `vX.Y.Z`. Every pack in a tag carries that version.
- Packs: `base` (`packs/base/**`, `content-schemas/**`, `decision-points/**`, `limits.yaml`, `simulation/thresholds.yaml`), `constitution` (`packs/constitution/**`), one per `packs/jurisdictions/<id>/**` and one per `packs/local/<id>/**`.
- Layer order and parents: base, constitution (parent base), jurisdiction (parent constitution), local (parent jurisdiction). A pack's directory id equals its `name`.
- `pack.yaml`: `name`, `version`, `layer`, `parent` (`null`, `name@semver`, or `{name, version}`), `effective_from`, `jurisdiction` (jurisdiction and local only), `status` (`draft` or `ratified`).
- `manifest.json` (per pack dir) and `release.json` (root) are generated by `npm run build:pack`. Never hand-edit them. Manifest paths are repo relative.
- Content schemas are JSON Schema 2020-12 plus `x-ui`, `x-guidance`, `x-checks`; `x-version` is also accepted. Unknown `x-` keys fail lint.

## Hash contract

This is the contract with can_server; the code is `tools/pack-hash.mjs` and nothing else may compute a pack hash.

1. Collect the hashed files of the pack. Excluded: `manifest.json`, `release.json`, `ratifications/**`, `CHANGELOG.md`, `ci/**`, `tools/**`, `test/**`, `node_modules/**` (these names only at the pack root), and dotfiles at any depth.
2. Read each file as bytes. For text files (`.json .yaml .yml .md .txt`) replace CRLF with LF first. `bytes` in the manifest is the length after that step.
3. sha256 hex per file.
4. Sort entries by path in byte order.
5. `pack_hash = sha256_hex(join("\n", ["parent:" + (parent_pack_hash or "none"), ...entries.map(e => e.path + "\t" + e.sha256)]))`.
6. The policy version string is `<name>@<semver>+<first 12 hex of pack_hash>`.
